# 第一个真实卷积点

这一步的目标：让 RISC-V CPU 通过现有 AXI 接口控制 PE，算对 AircraftCNN 第一层的一个原始卷积结果。

原来的 `pe_smoke.c` 是权重全为 1 的基础测试。本次新增 `conv1_point.c`，使用真实图片和模型权重。原 RTL、基础测试及任务一的验收入口保留。

## 现在已经能算什么

默认选择验证集第一张图片 `E-3/9-36.jpg`，第一层卷积的输出通道 0、位置 `(0,0)`。

这个位置需要 RGB 三个通道各取一个 3×3 小窗口，因此共有 `3×3×3=27` 项乘加：

```text
结果 = 输入0×权重0 + …… + 输入26×权重26 + 偏置
```

阵列有 16 行，测试将计算分成两批，并由 CPU 合并：

| 内容 | 默认标准答案 |
|---|---:|
| 前 16 项的乘加结果 | -15443 |
| 后 11 项的乘加结果 | -12409 |
| 偏置，只加一次 | -9127 |
| 最终原始卷积结果 | **-36979** |

第二批剩余 5 行的输入和权重都设为 0。只使用第 0 列、第 0 路，其余计算位置清零。这是一个卷积点，尚未执行 ReLU、重新量化、池化或完整分类。负的原始卷积结果是正常的。

## 如何用图形界面运行

重新打开工程助手，选择“模型部署：首个卷积点”：

1. “准备真实卷积点与标准答案”：只准备数据。
2. “运行首个卷积点 RTL 验证”：自动准备数据、编译新 C 程序、运行 CPU/PE RTL 仿真并核对结果。可以直接运行这个按钮。

以界面的本次结果汇总为准。正常用例通过，故意写错权重的用例按预期被拒绝，整个检查才会报告 `CONV1_POINT_RTL_PASS`。错误权重用例日志里的失败是有意触发的。

可选终端入口，在本工程目录执行：

```bash
bash project/scripts/run_conv1_point.sh
```

另一个实际点也可以通过参数指定，例如：

```bash
bash project/scripts/run_conv1_point.sh --validation-index 1 --output-channel 3 --row 41 --col 59
```

## 文件怎样配合

`prepare_conv1_point.py` 读取真实图片和量化模型，按照现有参考的 RGB、缩放和取整规则准备输入。它同时用独立 PyTorch 卷积核对标准答案，不导入会启动数据加载或训练的原脚本，不改写模型资料。

`conv1_point.c` 逐行装载权重，通过 `wr()` 送入输入，保持输入稳定，等待流水线传播后用 `rd()` 读取两批结果。两批在 PE 顶部都以 0 为初值；CPU 最后相加并加一次偏置。PE 权重使用符号与幅值编码，不能直接写普通有符号 INT8 的负数字节。

`soc_conv1_point_monitor.sv` 只观察实际总线，不代替 CPU 配置 PE。它检查 166 次 PE 写入和响应、两次真实 PE 读回，以及 CPU 实际写入 RAM 的三个结果。运行脚本再把全部配置数据与模型数据逐项核对。

本次为 CPU＋PE 的 RTL 验证，时钟周期 10 ns、外部存储响应延迟 1 ns；不等同于这段新程序已经通过门级 SDF 验证。下一步可以在这个正确基线上扩大到四个位置、十六个输出通道。
