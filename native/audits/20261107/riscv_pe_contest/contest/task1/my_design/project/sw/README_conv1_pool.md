# 卷积之后，CPU 怎样处理结果

前一步让 PE 算出了 16 个输出通道、四个相邻图片位置的卷积结果，共 64 个数。这一步继续处理这些实际结果，最终得到每通道一个池化输出，共 16 个数。

```text
PE 两批乘加
    ↓
CPU 合并部分和、加一次偏置：64 个原始结果
    ↓
CPU 执行 ReLU 和重新量化：64 个 0～127 的整数
    ↓
每通道四个相邻位置取最大值：16 个池化输出
```

## 三个处理步骤

ReLU 把负数变成 0。正数按模型的 Q24 规则缩放并四舍五入，最后限制到 0～127。这一层的缩放乘数从量化模型读取；当前为 16860，右移位数为 24。

```text
当原始结果 acc <= 0：q = 0
否则：q = (acc × multiplier + 2^23) >> 24
最后把 q 限制到 0～127
```

乘法使用 64 位中间量，避免 32 位溢出。例如，第一个实际原始结果为 -36979，因此处理后为 0。

四路分别代表某个 2×2 区域的左上、右上、左下、右下。最大池化把每通道这四个数中的最大值交给下一层。测试要求区域起点为偶数行、偶数列，与模型步长 2 对齐。

## 怎样确认算对了

Python 依据图片和原模型生成标准答案，并与独立计算核对。SoC 中运行真正的 RISC-V 程序：CPU 配置 PE，读回部分和，然后执行后处理。

独立监视器检查 258 次 PE 写入、128 次 PE 读取、304 个 CPU 实际 RAM 结果。304 个结果中有 272 个属于真实图片的计算链：128 个部分和、64 个含偏置结果、64 个量化结果、16 个池化结果。另有 24 个量化边界和 8 个池化边界，用于检查负数、舍入阈值、饱和、64 位乘法以及四个位置取最大值的行为。

同一个仿真器还分别运行故意写错权重、故意改错量化结果、故意改错池化结果的固件。三种错误必须在对应阶段被拒绝；负控日志中的失败是有意触发的，不表示正常测试失败。

## 哪些文件做了什么

| 文件 | 作用 |
|---|---|
| `conv1_pool.c` | 控制 PE，并在 CPU 上处理真实读回的结果 |
| `cnn_postprocess.h` | 可复用的 ReLU/Q24 量化和四数最大值函数 |
| `prepare_conv1_pool.py` | 从模型准备数据、后处理标准答案和边界用例 |
| `soc_conv1_pool_monitor.sv` | 只观察总线，独立检查实际结果 |
| `run_conv1_pool.py` | 独立冻结源码、编译、运行正常与错误用例并汇总 |

本阶段没有修改原 RTL、原 smoke 或先前单点/并行卷积程序。本次属于第一层小区域的 RTL 功能验证，未执行整层或整网，也未重新运行综合或 SDF。
