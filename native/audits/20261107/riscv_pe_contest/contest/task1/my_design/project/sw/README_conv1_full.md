# 第一层完整计算：conv1_full.c

这个程序让实际 RISC-V CPU 控制现有 PE，处理一张真实图片的整个第一层：

```text
3×130×130 图片整数
    → 32×128×128 个卷积结果（加偏置）
    → CPU 执行 ReLU 和 Q24 重新量化
    → 2×2 最大池化
    → 32×64×64 个 uint8 结果
```

它沿用当前 RTL、MMIO 地址、256 KiB 固件 RAM 和 `cnn_postprocess.h` 的整数规则。源码存在或编译通过不等于完整仿真已经通过；实际结果以运行入口保存的本次汇总及独立监视器检查为准。这一步仍是第一层，后面的卷积和全连接尚需连接。

## 怎样拆分工作

一个输出点需要 `3×3×3=27` 项乘加，分为前 16 项和后 11 项，第二批多余五行补零。每次使用全部 16 列和四路输入：

- 16 列对应 16 个输出通道；32 个通道分成两组。
- 四路输入对应一个 `2×2` 区域的左上、右上、左下、右下位置。
- 两批部分和加在一起，再给每个通道加一次偏置。
- CPU 对四个结果分别量化，取最大值得到一个池化结果。

一个“计算块”覆盖 16 个通道、一个池化位置，产生 16 个输出字节。每组有 `64×64=4096` 个位置，两组一共 8192 个计算块。编号顺序是：

```text
tile = 通道组×4096 + 池化行×64 + 池化列
```

## 为什么不用反复装载权重

第一层的权重对所有图片位置都一样。启动时将权重写入现有 SRAM 的四个地址：

| SRAM 地址 | 保存内容 |
|---|---|
| 0 | 通道 0～15，前 16 项 |
| 1 | 通道 0～15，后 11 项，其余行补零 |
| 2 | 通道 16～31，前 16 项 |
| 3 | 通道 16～31，后 11 项，其余行补零 |

随后只切换 SRAM 地址和更新输入，不再重新写权重。每批输入写好后执行 64 条明确的 `nop` 指令，保持输入静止，等待横向数据和向下部分和稳定，再读回结果。每次 MMIO 仍保留原来的顺序屏障；这不是连续每拍输入的流式方案。

按当前程序，初始化是 389 次 PE 写入；每个计算块是 34 次写入、128 次读取。默认完整范围合计 **278917 次 PE 写入、1048576 次读取**。检查运行时应同时验证实际事务、部分和与最终池化结果，不能只看程序返回成功。

## 怎样控制内存

程序只保存：

- 一张量化输入：50700 字节。
- 第一层权重：864 字节；32 个偏置：128 字节。
- 最终池化输出：131072 字节。
- 当前小块的 32 个打包输入、64 个第一批部分和，以及少量局部变量。

**不分配整层 32 位卷积结果，也不把标准答案放进 CPU 固件。**标准答案由独立测试环境保存和比较。代码、数据和栈的实际总占用还要通过链接报告确认，原来的链接器也会检查与栈是否冲突。

结果数组为 `volatile uint8_t conv1_full_output[131072]`，使用 CHW 顺序：先存通道 0 的 `64×64` 图片，再存通道 1，以此类推。索引为：

```text
通道×4096 + 池化行×64 + 池化列
```

`conv1_full_progress[4]` 是普通 RAM 中的进度：阶段、最后完成的块编号、完成块数、写入结果字节数。它不新增硬件寄存器。

## 小范围调试与错误检测

默认编译整个范围。调试时可在编译命令中指定 `C1F_TILE_START` 和 `C1F_TILE_COUNT`，例如只计算前两个块；这种运行只能证明相应小范围正确，不能当作整层通过。

可选负控宏 `C1F_INJECT_WEIGHT_ERROR=1` 会破坏 SRAM 地址 0 中第一个权重；`C1F_INJECT_POOL_ERROR=1` 会改错首个实际池化结果。正常运行均不启用。测试环境应检查这些错误确实会被拒绝。

生成的 `conv1_full_data.h` 只包含真实输入、硬件编码的权重、偏置和量化参数。负数权重使用当前 PE 所需的符号幅值编码，不能直接改用普通 `int8_t` 的原始补码字节。

## 怎样运行和理解验证结果

在图形界面点击“运行完整第一层”，也可以执行 `project/scripts/run_conv1_full.sh`。入口会自动准备图片、编译固件和检查结果。

为了缩短电脑上的验证时间，默认把 8192 个计算块分成四段同时仿真。每段仍由真实 RISC-V RTL 执行 C 程序并控制原 PE；检查各段的实际部分和与输出，再按图片位置合并，确保全部 131072 个输出都检查到、没有重复或遗漏。**这是四份仿真一起检查，芯片内部仍是一个 CPU。**

四段各自复位和装载权重，所以实际累计为 280084 次 PE 写入、1048576 次读取；前面提到的 278917 次写入对应只启动一次、连续跑完整层的安排。不能把四段同时运行的等待时间当成单 CPU 的推理耗时。

需要验证一次启动后连续跑完时，可执行 `project/scripts/run_conv1_full.sh --shards 1`，耗时更长。小范围调试可使用 `--tile-start` 和 `--tile-count`；这些参数只改变本次测试范围，不改变 RTL。每次查看该目录的 `RESULTS.md` 和 `summary.json`，确认本次覆盖范围和验证方式。
