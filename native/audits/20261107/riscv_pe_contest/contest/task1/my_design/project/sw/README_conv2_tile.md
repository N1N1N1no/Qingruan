# 第二层卷积小区域：conv2_tile.c

这个程序接着上一阶段做：把**已经验证过的 CPU Pool1 输出**作为输入，在现有 RISC-V＋PE 电路上计算第二层的一个 `2×2` 区域。它覆盖全部 64 个输出通道：

```text
上一步 CPU 得到的 32×64×64 个 Pool1 整数
    → 选取第二层的四个相邻卷积位置
    → 每个位置计算全部 64 个通道，共 256 个原始结果
    → CPU 执行 ReLU 和 Q24 重新量化
    → 每个通道做一次 2×2 最大池化
    → 得到 64 个 Pool2 整数
```

本次测试从上一阶段保存的输出启动一个新固件，便于独立排错；它尚未在同一次 CPU 启动中串起两个完整层，也没有完成整个第二层或完整 CNN。源文件和编译成功仅代表程序已准备好，实际是否通过要看本次仿真和独立监视器结果。

## 第二层为什么需要更多批次

第一层输入只有三个通道，一个卷积结果需要 27 项。第二层输入有 32 个通道，因此每个结果需要：

```text
32 个输入通道 × 3×3 个位置 = 288 项乘加
288 ÷ 16 行 PE = 18 批
```

每批使用全部 16 列和四路输入：列对应不同输出通道，四路对应左上、右上、左下、右下位置。64 个输出通道分成四组，因此共运行 `4×18=72` 批。每批都会重写 SRAM 地址 0 的权重，然后更新 16 行输入，保持输入稳定并等待 64 条明确的 `nop`，最后读取 64 个部分和。

主循环执行顺序为“通道组 → 乘加批次 → 列 → 路”。两批之间不依靠旧 PE 输出继续累加；CPU 在最后把每个结果对应的 18 个实际部分和相加，再加一次偏置。

## 输入和整数规则

生成的 `conv2_tile_data.h` 只提供输入、权重、偏置、区域位置和量化比例，**不把标准答案放进 CPU 固件**。输入是上一阶段真实 CPU 结果，不能拿 Python 标准答案冒充；生成器和运行记录应核实其来源及哈希。

输入使用 CHW 顺序的 `uint8_t[32][64][64]`，权重使用 PE 所需的符号幅值字节，排列为 `[288][64]`。`C2T_ROW`、`C2T_COL` 是四个卷积位置中左上位置的坐标，必须为 `0～60` 范围内的偶数，才能对应一个合法的池化窗口。

CPU 后处理直接复用 `cnn_postprocess.h`：负数先变成 0，正数用 64 位中间量按模型规定的 Q24 比例舍入，再限制到 `0～127`。四个位置量化后取最大值。每个阶段从实际的 volatile 结果重新读取数据，交给下一阶段。

## 怎样检查结果

`conv2_tile_results` 是普通 RAM 中的 5184 个 32 位结果：

| 数组索引 | 内容 | 数量 |
|---|---|---|
| 0～4607 | 四组、十八批的 PE 部分和 | 4608 |
| 4608～4863 | CPU 累加并加偏置后的原始卷积结果 | 256 |
| 4864～5119 | ReLU＋Q24 量化结果 | 256 |
| 5120～5183 | 池化结果 | 64 |

先完成所有部分和，再依次写入原始结果、量化结果、池化结果。独立监视器应同时检查 **6978 次 PE 配置写入、4608 次读取，以及这 5184 个 RAM 结果**。标准答案留在测试环境中；程序正常返回不能代替这些检查。

可选负控宏为 `C2T_INJECT_WEIGHT_ERROR`、`C2T_INJECT_INPUT_ERROR`、`C2T_INJECT_REQUANT_ERROR`、`C2T_INJECT_POOL_ERROR`，设为 1 时故意改错对应数据。输入和权重负控使用生成器挑选的 `C2T_FAULT_TERM`，保证该输入和对应权重非零，使错误对算术有实际影响。正常测试不启用这些宏。

完整 Pool1 输入占 131072 字节，第二层权重占 18432 字节，结果数组占 20736 字节，另有偏置、代码和一个 1152 字节的局部输入窗口。程序不申请整层卷积输出；实际固件、数据与栈能否放入原 256 KiB RAM，由原链接脚本继续检查。
