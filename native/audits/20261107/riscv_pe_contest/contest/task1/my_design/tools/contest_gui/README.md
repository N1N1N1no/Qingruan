# RISC-V 与 PE 工程助手

双击桌面的 **RISC-V与PE工程助手** 启动。不需要打开终端或输入命令。

1. 点击“工具与运行检测”，检查工具、内存、磁盘和正在运行的工具进程。
2. 在左侧选择步骤，查看它做什么、需要先完成什么、结果放在哪里。
3. 点击“运行这一步”，在实时日志里查看进度。
4. 从“历史结果”选择某次运行，查看汇总、日志和时序报告。

“实时日志”中的“查看错误与警告”可筛选当前窗口的内容；选择保存的日志后，点击“筛选完整文件”可逐行扫描整个文件，包括窗口中已被截掉的早期错误。筛选会保留行号；是否通过仍以本次汇总为准。

“一键 RTL 基础流程”依次运行准备工程、编译 C、权重存储器测试、AXI/PE 测试和完整 RTL 检查。按住 Ctrl 选择多项后，也可以按列表顺序运行；遇到失败会停下。

“模型部署：首个卷积点”提供两个新按钮：

- **准备真实卷积点与标准答案**：从真实图片和已有模型提取 27 个输入、27 个权重、PE 使用的权重编码及偏置，保存前 16 项、后 11 项和最终结果的标准答案。
- **运行首个卷积点 RTL 验证**：自动准备上述数据，编译 `project/sw/conv1_point.c`，让真实 RISC-V CPU 控制 PE 分两批计算。独立监视器检查 166 次 PE 写入、2 次结果读取，以及 CPU 保存到 RAM 的两个部分和与含偏置结果；还会运行故意改错一个权重的负控，确认错误确实会被检测。

可以先用第一个按钮查看数据，也可以直接点击第二个按钮一键完成测试；不需要先手动生成头文件。每次结果保存在独立的 `task1/work/conv1_point.*` 目录，原来的 `pe_smoke.c` 和基础测试保留。这一步验证一个真实卷积点的 RTL 功能；完整 CNN 推理和这个新程序的 SDF 验证仍需后续完成。它们不包含在“一键 RTL 基础流程”中。

“模型部署：卷积并行计算”中的 **运行 4 位置 × 16 通道 RTL 验证**，会编译 `project/sw/conv1_tile.c`，让四路输入对应四个图片位置、十六列对应十六个输出通道。27 项仍拆成 16 项与 11 项两批；程序按输入数组、权重数组和项数安排批次，读回两批各 64 个部分和，再由 CPU 给每个结果加一次对应通道的偏置。独立监视器检查 258 次 PE 写入、128 次读回，以及保存在 RAM 的 128 个部分和与 64 个最终结果；错误权重负控检验检测是否有效。每次在 `task1/work/conv1_tile.*` 保存新数据、日志和汇总，可直接运行，无需先手工生成头文件。

这个并行测试完成第一层中一个小区域、十六个通道的 64 个原始卷积结果（含偏置）；ReLU、重新量化、池化、完整网络和新程序的 SDF 仍需后续接入。原来的单点测试继续保留。

同组新增 **运行卷积、ReLU、量化与池化**。这个独立测试使用 `project/sw/conv1_pool.c`，在 PE 的真实卷积结果之后，让 RISC-V CPU 执行 ReLU、与整数参考一致的 Q24 舍入和 0～127 饱和，再对每通道的四个相邻位置做 2×2 最大池化，得到 16 个输出。池化窗口从偶数行、偶数列开始，与模型步长 2 对齐。每次独立生成 `task1/work/conv1_pool.*`，无需先运行旧按钮。

新的测试检查 258 次 PE 写入、128 次 PE 读回和 CPU 实际保存的全部中间及最终结果，还在同一个 CPU 程序中检查 24 个量化边界和 8 个池化边界。故意改错权重、量化结果、池化结果的三种负控都必须被拒绝，正常计算才报告通过。这个按钮完成第一层小区域的“卷积→ReLU→量化→池化”，尚未完成整层、第二层或完整图片识别，也不代表新程序已通过 SDF。旧并行卷积按钮保留原来的验证范围。

同组的 **运行完整第一层** 使用 `project/sw/conv1_full.c` 处理整张图片的第一层：输入为 `3×130×130`，卷积产生 `32×128×128` 个结果，经过 ReLU、Q24 量化和 2×2 最大池化后，输出 `32×64×64`，即 131072 个字节。程序先将权重装入 PE 的四个 SRAM 地址，随后重复使用；每个小块立即池化，能容纳在原来的 256 KB RAM 中。标准答案只保存在电脑侧，固件包含真实输入、权重和偏置。

完整第一层会先预检开头、通道切换与末尾，再验证错误权重、错误池化输出，最后运行完整范围；逐个检查 PE 部分和及 CPU 实际写入 RAM 的输出。默认将测试分成四段同时仿真，每段独立启动 CPU，最后合并实际输出并检查没有重复或遗漏。这是电脑上的验证方式，芯片内部仍是一个 CPU；并行验证用时不代表单 CPU 推理延迟。脚本参数 `--shards 1` 可验证一次连续执行，耗时更长。

默认无需先运行旧按钮，结果放在 `task1/work/conv1_full.*`。完整 CPU RTL 仿真比小区域慢，日志会持续显示四段各自的运行时间和分块进度。它只验证第一层，后续各层和新程序的 SDF 仍需接入；单独生成标准答案也不等于 CPU 仿真通过。

“模型部署：第二层卷积”新增 **运行第二层小区域**。先准备好完整第一层的通过结果，这个按钮会读取该次 CPU 实际输出的 `32×64×64` 个字节，而不是使用 Python 的标准答案代替输入。它让 CPU 控制 PE 计算第二层一个 `2×2` 卷积区域、全部 64 个输出通道，再完成 ReLU、Q24 量化和池化，得到 64 个池化值。

第二层一个输出要合并 `32×3×3=288` 项，所以分 18 批使用现有 16 行 PE。独立检查 6978 次 PE 写入、4608 次读回、全部 5184 个实际 RAM 中间及最终结果，并验证权重、输入、量化和池化四种错误会被拒绝。来源记录或哈希错误也会拒绝运行。每次结果放在 `task1/work/conv2_tile.*`。

这一步通过文件把前一次第一层的实际输出交给新的第二层固件：新固件包含完整 Pool1 输入、第二层权重和偏置，标准答案保留在电脑端。它验证了两层之间的数据交接和第二层小区域计算；整个第二层、同一次启动连续执行各层、最终分类及新程序的 SDF 仍需后续完成。脚本可用 `--row`、`--col` 选择 0～60 的偶数坐标，补充检查图片边缘位置。

旧单 PE、阵列和 AXI 综合步骤沿用原脚本，会更新对应的 `project/build/dc_*` 产物。整机和验证脚本继续生成独立的 `task1/work/*` 目录。上游产物变化后，下游可能需要重新执行；界面保留脚本原有的哈希匹配检查。

“完成”表示当前步骤执行结束，“通过”只对应该次测试的范围。综合完成不能代替时序验收。整机 SDF 经已诊断门的等价尺寸修复后，已通过当前 C 测试及全部反标检查；每次仍按本次汇总判断，旧失败历史保留。这不代表完整 CNN 推理或全部工艺角验证通过。

整机综合会严格核对被修复门的类型、引脚、连线和库布尔函数，目标签名变化会拒绝执行并要求重新诊断。修复改变真实映射门的驱动尺寸，重新生成配对网表、面积与时序报告，不修改原 SDF 数值、库模型或时间预算。

点击“停止当前任务”会清理该界面启动的进程及其子进程，原来的交互 DC 会话保留。多个界面同时打开时，只允许一个执行工程任务。

界面日志与记录位于 `task1/work/gui_runs/`，避免在运行时修改冻结源码。每次运行记录实际命令、退出码、日志和结果位置，便于排错。

Python 入口为 `tools/run_contest_gui.py`；`tools/start_gui.sh` 自动选择本机已安装 Tkinter 的 Python。界面基于 Tkinter，无需安装 PyQt 等额外依赖。

本机为清晰显示中文，使用用户目录 `~/.local/share/riscv-pe-gui/runtime/` 中的 Tk 图形组件（从 Ubuntu 软件包解压，不修改系统安装）。启动器自动选择该组件；调用综合和仿真工具前会清除仅属于界面的运行库路径。

第二层组新增 **运行完整第二层**：接收已验证的完整第一层实际输出，计算 `64×62×62` 个卷积结果，经过 ReLU、Q24 量化和池化，得到 `64×31×31=61504` 个字节。最多暂存 32 个位置的部分和，同一批权重供这些位置重复使用，保持原 256 KB RAM。默认分四段独立 CPU 仿真，检查全部 4428288 个 PE 部分和并合并实际输出。完整仿真比小区域耗时长，可在日志看进度；具体通过情况以本次结果目录的 `summary.json` 和 `RESULTS.md` 为准。此步骤仍从保存的 Pool1 数据另行启动，尚未在一次 CPU 启动中串起两层，也不代表整个 CNN 已完成。结果位于 `task1/work/conv2_full.*`。
