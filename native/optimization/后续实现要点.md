# 后续实现与验证边界

当前已有 MAC/GELU/量化及统一 RV32 微内核通路。尚不能宣布最优：整图剩余浮点/重排仍在 CPU，公开参考精度未通过，完整 SoC 对比未完成。

## 浮点与归约

- 复用已验证的 HardFloat FP32 单元，覆盖 DQ、二元 Add/Mul、MAC 的 INT32→float32→scaleA→scaleB→bias，以及 LayerNorm/Softmax。现有完整硬件数据流证明中这些仍由主机执行；真实 RV32 固件将执行软件版本，不能漏计其代价。
- LayerNorm 必须保持当前 C 的顺序：逐项 sum+=x、ss+=x*x，mean=sum/N，var=ss/N-mean*mean，inverse=1/sqrt(max(var,0)+eps)，输出逐次减/乘/乘/加，禁止隐式 FMA。模型宽度有 96、192、384、768、1536；不能假设全部行可放进 4 KiB。
- 现有 256 个 16×8 SRAM 可暂存 1024 个 float32。对宽度 1536 分块保持归约顺序，输出阶段重新读取相应块；较小几何 128 宏对应 512 个 float32。scale/bias 可按 16 个元素装入小缓冲，避免为完整向量增加大量 FF。
- Softmax 当前最后轴 49 个通道；实现 max、原 expf 运算、顺序求和和逐项除法。先核对本机 RV32/newlib 的 expf 实现与许可来源，再逐项验证；近似替换不能直接声称对旧 C 逐位一致。HardFloat 现有 float→int 使用 RNE，若 expf 算法需要 C 截断转换，必须单独实现 RTZ 并测试。
- 65 个剩余 DQ 为标量量化参数，另两个为 96/1000 元素 INT32 bias；不能把它们都当成 INT8 DQ。二元广播中既有标量/末尾通道，也有 `[windows,1,49,49]` 的中间轴重复。

## 重排

- 176 个连续视图已去除复制。剩余 Transpose 应通过多维步长 DMA；Slice/Concat/Gather 的连续子块可使用已有二维 DMA。
- 多维转置可以用输出顺序的形状和源字节步长描述，目标地址连续。按最大连续后缀作为一行，源端使用多维计数器逐行发起读取，目标 writer 保持同一二维命令。中间行的 command_last 必须改成全局最后一行，row_last 保留。
- 递增地址可用逐轴进位，每次进位一周期。`(dim-1)*stride` 等回卷量在命令开始时计算并存储，避免运行路径中的多级乘除。读写错误/取消必须排空已发布的 AXI 事务。

## 整机证据

- `work/rtl-model/` 首图已验证全部 MAC/GELU 的完整数据流，CPU/打包在主机，不能当作完整 RV32 周期。
- `work/rtl-model-quant/` 是加入全部 166 个量化节点的独立复验目录。
- `work/accel-model/manifest.json` 只证明完整 RV32 固件和 RAM 镜像已生成。执行、精度、整图周期必须另外验证。
- 整机综合必须确认当前 top 为 `soc_accel_top`，含实际 CPU/control、唯一后端、全部 SRAM 且无未映射逻辑。读取失败后 DC 可能继续保留先前设计；不能仅凭 link/compile 或 SRAM 数量判断整机成功。
- 先前错误实例参数转换的报告保留在 `soc-synthesis/*.failed-control-import.*`；它们不构成任何整机面积证据。当前修正版增加了明确的 top、CPU/control 数量及外部接口检查。
- 最终需完整 RV32 延迟、完整 SoC 面积/STA、相同 RAM/时钟条件和精度门槛，才能按候选集合实测 ADP 排名。
